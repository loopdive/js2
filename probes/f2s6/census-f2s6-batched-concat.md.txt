## manifestNeeds
Vocabulary the runtime manifest lacks today, each tied to a measured fact:

1. A FUNC capability record whose import FIELD is a scheme, not a name. `RuntimeHostCapabilityFuncRecord.field` is `string` (runtime-host-capabilities.ts:176); the F2-S2 scheme precedent (`{scheme: "literal" | "literal-utf16-hex"}`, :136-142) exists only on the GLOBAL arm. Needed: a func field scheme such as `{ scheme: "arity-suffix", prefix: "__concat_" }` — the physical field is derived from the arity at resolve time (measured host fields: __concat_3/4/5/6/7/8/9; the JS provider runtime.ts:11416 accepts any N by prefix).

2. PARAMS as a scheme. `params: readonly Value[]` is fixed-length (:177); the family is `externref × arity -> externref`. Needed: `{ repeat: "externref", min: 3, max: null }` on the host record, with `results: ["externref"]` fixed. The value union already has `externref` — no new value type.

3. An ARITY RANGE that is a provider fact, read by the pass. Host: min 3 (IR pass), unbounded max (measured __concat_9). Native: min 3, max 8 (native-batched-concat.ts:20-21), copied by hand into integration.ts:3683 as the literal `8`. The record should carry the range so the pass cap is derived, not duplicated; the `joinNine` fence (tests/issue-4566:420) pins the native max.

4. RuntimeProviderImplementation family kinds. `host-callable` names exactly one `RuntimeHostCapabilityFuncId` and `runtime-callable` exactly one `symbol` (runtime-manifest.ts:485-495). Needed: `host-callable-family { capability: "string.concat.many" }` (field derived per arity from the record scheme) and `runtime-callable-family { symbolPrefix: "__str_concat_", min: 3, max: 8 }` (nativeStrHelpers cache key at native-batched-concat.ts:40). Two provider rows under one feature `js.string.concat.many`, selected by a policy.

5. IntrinsicSignature cannot say variadic (`params: readonly IrType[]`, intrinsics.ts:184-188), and the symbols `string.concat$arityN` / `async.string.concat$arity5` are NOT closed IntrinsicIds (0 hits in intrinsics.ts; they are free-form `irIntrinsicFuncRef` symbols, string-runtime.ts:44/67, async-semantic-runtime.ts:7). Either (a) add a signature FAMILY (`paramsScheme`) and register the family once, validating arity per use, or (b) keep the symbols outside INTRINSIC_DEFINITIONS and let the provider row's arity range be the only check — (b) is byte-neutral and smaller; (a) is what the R6 "closed contract" wants. Also fold `async.string.concat$arity5` into the same family (today it is a second symbol and a second arm for the identical lowering).

6. A PASS policy, distinct from the provider policy (see answer 4): `StringConcatManyPolicy { batch: "host" | "native" | "off"; maxArity: number | null }`, frozen from the lane like the F2-S5 `stringConcat` policy: `nativeStrings ? (standalone ? {native, 8} : {off}) : strictNoHostImports ? {off} : {host, null}`. The freeze must happen BEFORE the pass (the pass creates the demand, so no demand scan can gate the provider rows; the policy itself is the demand signal).

7. Classification: `__concat_N` reaches hostImportInventory through the `builtin` fallthrough intent (import-manifest.ts:323) → `legacy-semantic / ecmascript-runtime` (host-import-policy.ts:76,148). A typed intent (e.g. `string_method`-like → family `strings`) would be the manifest-era spelling; it changes no ratcheted count (answer 6).

## risks
- Both host-import ratchets sit AT their ceilings today (nativeFirst imports 395 = max 395; compat core legacy-semantic 23 = max 23, measured on the unpatched tree). Any slice that adds one import anywhere in the 33 probes fails `quality`; a manifest row that PRE-registers env.__concat_N (instead of late-minting on demand) would add imports only where they are used, and dead-import elimination removes unused ones — but this was not measured, so a pre-registering design must run the gate before claiming neutrality.
- Byte identity depends on IMPORT ORDER, not on funcidx shifting: the flush moved 0 refs in every host cell (stable handles), but __concat_N's index is 'after every earlier import in this compile' (5 → #0 after dead-elim on the small fixtures; #21 of 27 on ASYNC; #1 after number_toString on CATNUM3). Moving registration to freeze time or to the base string block changes bytes in every batching cell — the F2-S5 V-A style 'byte-identical' fence would fail by design, and #3522:395 pins host and legacy twins to the same spelling.
- The pass CREATES the demand it needs a provider for — there is no pre-pass demand scan possible (unlike eq/len/concat-pair). The policy must be frozen from the lane before the pass; a design that tries to 'request the feature on demand' inside the pass would be a late request after the manifest freeze.
- Two producers stay outside the manifest after the slice: compileBatchedConcat (legacy host twin, reached on every demoted gc-host function with a 3+ chain, e.g. CATNUM3 and the gate's `errors` probe) and the legacy native twin (standalone/wasi demoted functions, ASYNC wasi ×2). A policy that says 'wasi: off' is then true for the IR pass but false for the module — must be stated, not hidden.
- The native max-arity 8 lives in two places (native-batched-concat.ts:21 and the literal 8 at integration.ts:3683); the CAT9 standalone cell (batch-cap 9>8, pairwise) and tests/issue-4566:420 are the only fences. If the record carries the range, delete the literal, do not add a third copy.
- `async.string.concat$arity5` is a second symbol for the same thing with a separate resolve arm and separate producer (async-ir-planning.ts:849); unifying it is byte-neutral in principle (same ensureLateImport/ensureNativeBatchedConcat call) but touches #4124/#4574 pins — do it inside this slice or explicitly defer, not accidentally.
- The `!ctx.wasi` terms in both selectors are dead (wasi ⇒ nativeStrings; wasi ∧ standalone throws at target-profile.ts:69); `!ctx.strictNoHostImports` is live only for gc-strict. A policy derivation must keep gc-strict at `off` (measured: no batching, no env request, no allowlist entry) or the strict allowlist gate fires.
- F2-S5's text 'a late registration here shifts every defined funcidx' is not what this tree measures (0 refs, 0 map entries moved across 4 host cells); a fixture with live-regime bodies could differ, and none was in this set — do not cite the shift as a reason to change registration timing without measuring on such a fixture.
