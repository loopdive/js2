## 2. IR-side facts for candidate (ii)
- `assessModuleInit` (`ir/select.ts:10588`): Gate 1 shape, Gate 2 call graph `:10656-10668` — `external-call` for any non-local call, `call-graph-closure` if a local callee ∉ `claimedFuncs`. On the production branch with no individually-claimed top-level function the assessment uses an **empty** claimed set (`select.ts:1046-1053`), so any local callee rejects.
- Measured (`g1-variants.mts`): `let z = h()` / `h(a:number)` / `h();` with typed `h` → `call-graph-closure` + from-ast `direct call to "h" has no exact AST-site plan in <module-init>` (`ir/from-ast.ts:6516-6521`; plans built per population statement at `ir/integration.ts:3023`); `h(a:any)` init, `setup();` stmt, `console.log(1)`, `m.set` → **emitted overlay** (legacy=1, ir=1, census still 1/1); `Object.freeze`, arrow/fn-expr initializers → `body-shape-rejected`.
- Prepared grammar `preparedExactLexicalModuleInit` (`index.ts:4262-4430`): single-declarator `let/const` with initializer or exact scalar assignment (`:4192`). The reachability scan `:4100-4117` refuses any initializer containing a function-like node **or an identifier resolving to a source function/class**; introduced by `d59b8693ad` (Calendar retirement) together with the component preflight `preparedLexicalComponentPreflightFailure` (`:4433-4475`: no `importedCalls`, exact env import manifest, host-callback-maker ABI, host-Date ABI) and `rejectPreparedLexicalComponentBeforeMutation` (`:4477-4499`). The refusal is **component closure for all callees**, not closures only: a Prepared body is sealed before legacy bodies compile, so any callee whose ABI/index the IR does not own would be linked unsealed. Admitting calls therefore needs (a) Gate 2 evaluated against the real claimed set, (b) `directCalls` plans for the population (exist), (c) grammar arms for call statements/initializers with R2-owned callees only, (d) builtins via the existing import-manifest preflight.

## 4. Recommendation — next slice = (i), with the test262 truth stated in the issue

**Slice:** rename/extend `moduleInitPopulationIsCallFree` → `moduleInitPopulationIsPassTwoStable`: refuse on `ArrowFunction`, `FunctionExpression`, `ClassExpression`, `Decorator`, `AwaitExpression` (and keep `TaggedTemplateExpression`/`CallExpression`/`NewExpression` **admitted**); keep `hasAsyncGraphInit || moduleInitChunkingRequired` forcing; no other change. Rationale to record: the registry inliner never reaches a direct init statement (measured with `JS2WASM_IR_INLINE=0`), and IR-emitted callees never enter the registry (`declarations.ts:5033-5035`).

**Acceptance signature:**
1. Census: 13 closure-free call-bearing shapes `1/0` on gc/host-deferred/standalone/wasi; 6 closure-bearing shapes `1/1`; a 17-statement population `1/1` (chunk-forced); IR-owned `0/0`.
2. Byte identity vs `JS2WASM_TEST_FORCE_MODULE_INIT_PASS2=1` for the closure-free family on gc/host-deferred/standalone; wasi: `WebAssembly.validate` + runtime parity + identical import surface (document the dead `"\n"` data segment as the only diff).
3. Mutation: admitting `ArrowFunction` in the predicate must break the byte-identity pin on the c21 shape (`h(a:any)` called inside an arrow) — proves the closure refusal is load-bearing.
4. Diagnostics parity: error count unchanged on the 319-file test262 compile sample (probe `g1-t262-compile.mts`, expected 0 divergence — all sampled files are closure-bearing and keep two passes); the `for-in/cptn-decl-itr.js` case pins that dedupe stays on the two-pass route.
5. `check:ir-fallbacks` bare unchanged; poison seam still fails a gated shape; existing single-pass and compile-once suites green with the two pins above moved.

**Say plainly in the issue:** gap 1 is **not conformance-visible through pass-count work**. On test262 every module-init population is closure-bearing (harness function expressions) and 38–52% are chunked, so pass 2 is the emitting pass there; the only route that retires those 318 rows is pass-1 replacement, which this probe shows requires a closure-fact discovery the IR inventory does not yet carry (6/89 async regressions when removed). The follow-up design item after (i) is therefore "closure pre-lift inventory ahead of bodies" (the facts `registerClosureBindingInfo` writes at `arrow-phases.ts:1291-1322`), measured against the `p2only` failure set (`Promise/allSettled/iter-assigned-undefined-reject.js` et al.) — not (ii), which has zero test262 yield until the selector admits harness-shaped populations.
