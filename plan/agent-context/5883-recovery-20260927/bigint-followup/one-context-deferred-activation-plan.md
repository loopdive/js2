## Decision

Use one CodegenContext and one ProgramAbiSession. Defer **semantic expansion**, not just a boolean and not already-mutated runtime registration. Preparation is allocation-free compiler metadata. Exact original-vector lowering records a typed pending operation; it does not call A/B/D or set dirtiness. After selected source bodies are settled, compute committed occurrences, activate once if nonempty, register the complete dependency closure while registration is still open, expand recorded sites, then freeze provider inventories and run finalizers once.

Do NOT reserve real funcs/types/globals for conservative demand and hope DCE restores parity. `funcMap`, seeder sets, allocation counters and helper-presence decisions already affect source lowering. A detached numeric function reservation is still an allocation. Prepared handles in this design are symbolic recipe identities, not `FuncHandle` numbers. This is the concrete way to prevent preparation leaking without needing a whole-context rollback.

This requires a bounded **codegen staging representation plus occurrence ownership**, neither present today. It is more than B's gate change. The design below specifies that infrastructure and its consumers. It is not permission to implement broad prototype cutover, change source admission, bypass arbitrary iterator overrides, recompile source bodies, or add a new failed-input outcome. Missing ownership/staging support is a development blocker to shipping, not a runtime null/miss/success implementation.

## 1. Exact admission and meaning of committed

Keep `call-namespace-static.ts:2903–2907` unchanged in meaning: existing native eligibility, intrinsic non-subclass all/race, and resolve/then override in THAT call's SourceFile. Preserve literal priority, Set/Map priority (:2915–2997), and natural argument compilation plus externref/f64 vector shape decision (:3011–3021). Whole-module facts may bound metadata collection only. They never choose a source lowering or force a vector cast.

At the existing observable original-vector branch (:3029–3050), retain argument emission once and its actual carrier type. Replace the immediate call to `emitStandalonePromiseCombinatorDrive` with a pending captured-drive operation whose input is the retained original carrier and whose result contract is externref (the current emitter returns EXTERNREF at `promise-combinator-drive.ts:521`). Do not evaluate arg0 again during expansion. Do not register helpers just to discover that return type.

A committed occurrence is `(context, exact source/unit identity, selected body epoch, emission occurrence id, method, actual carrier family)` with a retained path through source publication and all containing regions. AST node/span is provenance, not ownership. Two visits to one AST call get two occurrence ids. Commitment is selected source emission before normal optimizer/DCE, NOT a new runtime-reachability gate; ordinary published dead functions retain their existing admission policy. A type probe's abandoned body or discovery-only initializer is not a published source body.

Closure complication: a lifted body may be created during a probe and later genuinely reused. Keep the body epoch and its internal occurrences available for adoption, but do not treat its presence in mod.functions/funcMap/closure registries as publication. The later selected closure construction/callable publication installs a new ownership edge to that exact body epoch. Rolling back the first edge does not destroy a body that a later selected edge adopts. Conversely an orphan helper left by discovery is not a root.

No activation at an inner snapshot commit or at first branch encounter. Compute root ownership only after all direct/prepared source-body choices and module-init selection. This removes the causality flaw that defeated retry.

## 2. New bounded APIs and state

Proposed new `codegen/promise-vector-activation.ts` owns context-local state, never AST/global mutable state:

- `preparePromiseVectorFacts(ctx, sourceFiles)`: immutable scan facts/source identities and empty recipe/occurrence collections only. No ctx semantic flags, types/functions/globals/imports/strings, locals, helper cache entries, ABI registrations or diagnostics.
- `stageCapturedVectorDrive(ctx, fctx, provenance, inputRegion, carrier)`: typed pending node plus occurrence; no A/B/D ensure. Fact caching may miss a synthetic/eval SourceFile; the exact branch still stages correctly. Collection of possible sites must not depend on a prescan proving all future source exists.
- `stageProtocolChoice(ctx, owner, kind, legacyRegion, activeRecipe)`: source write/read/default site with exact legacy projection. Active recipe uses semantic operands/bindings, not a stale callback closing over mutable fctx or ctx indices.
- `sealSourcePublication(ctx)`: freezes selected body roots and adoption edges after routing settles. Verifies every pending required drive has an owner, not merely a registry entry; cancels unselected edges/epochs through their ordinary owner.
- `commitPromiseVectorActivation(ctx)`: EMPTY committed set -> discard metadata/select legacy projections, no protocol allocations; NONEMPTY -> enter registering once and consume frozen required recipes. No callback may re-enter source admission while this function is registering.
- `finishProtocolExpansion(ctx)`: expands committed sites and repairs only their explicit relocations/locals, checks the occurrence manifest against actual selected nodes, seals provider inventories, removes staging nodes before downstream structural/ABI finalization.

States: collecting -> source-sealed -> inactive-erased OR active-registering -> active-expanded -> provider-frozen -> finalized. There is no published partially active state. Ordinary pre-existing store/seeder demand remains independently active throughout collecting. A separate protocol-demand flag does not overwrite/reset legacy flags.

Do not expose `prepared` entries through existing registry getters. `isPromiseVectorProtocolActive` means committed active demand, not prepared metadata or helper presence. During registration, recursive ensures can see explicitly reserved active handles using their existing recursion guards, but runtime bodies are not yet published as ready. Active readiness requires complete bodies/providers, not a non-null handle.

## 4. Staged representation: not executable placeholder Wasm

Introduce a small typed codegen-only node family in `deferred-protocol-emission.ts`, represented explicitly in the pre-finalization instruction model (`ir/types.ts` / FunctionContext/body type seam). Kinds: required captured drive; legacy/active protocol choice; lazy-prototype seed edge. Each has input/output stack contract, body epoch/id, effect contract, owned operand regions, and a pure dependency recipe. No fake numeric funcIdx, ref.null return, true result, unreachable runtime stub, empty block pretending to return externref, or dummy reference to keep helpers alive.

For choice nodes, the legacy child is the exact old instruction sequence and old local allocation behavior; prepared-only locals/strings/functions are symbolic. Selecting legacy moves that same sequence into its parent, with no added Wasm block, instructions, allocation or changed relative order. Shared operands have ONE instruction owner: active expansion transfers them, never aliases them into both alternatives. Required drive nodes have no executable legacy substitute; every selected node activates, every discarded node disappears with its owner.

Before source seal, instruction relocation/late-import/global-fixup walkers must recurse through emitted operand/legacy children exactly once, and ignore symbolic recipes. Concrete code: registry/imports.ts global fixup :456/:582–622; function shift walkers :847–899 and :1167–1215; existing savedBodies/liveBodies/pendingInitBody handling. A node's symbolic helper/type handles are resolved only after active dependency registration. Native DCE/type-remap/stack-balance/serialization never receives staged nodes.

Source-time analyses that inspect opcode/tail/stack effects need explicit staging handling: tail-call conversion cannot mistake a pending captured drive for a direct call; structural peepholes, CSE/guard reuse, body-effect/inline candidacy and source IR selection must use the stated effect/stack contract or preserve the node. Do not classify it as pure/no-op/unknown-success. This is an infrastructure obligation, not a claim that today's generic walkers already support it. Avoid changing legacy projection decisions solely because a choice wrapper exists: inspect its legacy projection before commitment. If a pre-seal pass clones a region, it clones occurrence identity with an explicit derivation edge and fresh instruction objects; source-only discovery copies never become roots automatically.

Orphan pending bodies need a real disposition before the seal: leave them in the owner's unpublished staging arena, not mod.functions as serializable completed functions. A placeholder function identity may still be reserved by existing closure discovery, but its body publication remains staged. If later selected code reuses it, adopt and expand its exact epoch; if the ordinary pipeline replaces/discards it, apply that existing disposition. Do not materialize A/B/D for an orphan to satisfy validation and then claim no-opt-in parity. Preserving baseline physical allocation behavior at this seam is a mandatory receipt; DCE alone is not that receipt.

## 10. What is proved versus still to implement

Source proves why immediate helper registration and first-visit activation are unsafe, identifies actual rollback/publication sites, and shows a post-source interval before finalizer snapshots. Metadata-only preparation plus selected-epoch ownership removes those mechanisms without retry or speculative runtime allocations. This is the recommended one-context design.

It is not an existing-code guarantee. Three implementation gates require receipts before integration: complete pre-seal staged-node consumer coverage; operand/binding plans for earlier writes including conditional retention; selected-body ownership across all direct/prepared source callbacks and orphan reuse. Unknown coverage cannot be treated as no demand, and a missing recipe cannot produce null/success or exclude a valid case. If these gates cannot be completed within the held PR's authorized dependency budget, report the concrete implementation blocker to parent; do not ship half-deferred semantics or redefine full-behavior acceptance.
