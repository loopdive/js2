## Recommendation and decision boundary

Do not move B's current ensure into a conservative prescan. Do not use a module-wide override OR as the production admission predicate. A one-context deferred implementation is possible, but it is not a small reservation-gate change: current helper-presence predicates, seeder registries, statement retention and alternate override lowering all expose preparation as behavior. It also lacks a demonstrated way to remove preparation's allocation/order effects for strict no-opt-in byte parity.

Recommended exact alternative: an internal, bounded **fresh-context retry triggered at the existing committed admission point**. Attempt one uses unchanged legacy registration and all unchanged source gates until the first actual observable original-vector admission. At that point, before A/B/D registration, stop this attempt with a private control signal. Discard the entire module/context; perform one fresh generation with early semantic activation. No caller IR/helper body is rebuilt in the same context. No compiler or old backend is retired. Sources with no admitted original vector execute only the unchanged attempt and incur no runtime reservations or semantic writes.

This is a proposed implementation choice, not permission to implement a new compiler mode silently. Parent should explicitly choose the retry approach versus the larger deferred implementation below. Retry touches error-boundary plumbing and requires an audit of per-context versus AST/global mutable compiler state. If that isolation cannot be established, it is blocked; do not fall back to a loose early scan or certify deferred allocation as byte-neutral without evidence.

## Recommended lifecycle/API: prepared is compiler metadata, active is a fresh attempt

New internal module `promise-vector-activation.ts` owns a WeakMap keyed by CodegenContext, plus an unforgeable restart-signal class/type guard. Proposed API:

- `preparePromiseVectorDemand(ctx, sourceFiles)`: pure facts and immutable source inventory only; no funcMap/type/global/import/string insertion, dirty flags, seeder registry, declaration retention, or reader changes.
- `noteCommittedPromiseVectorAdmission(ctx, callNode, method, carrierFamily)`: called only at the existing observable + admittedVecShape branch. On initial attempt, throw the private restart signal **before** allocating new source-local/helper state. On active attempt, record the actual witness and continue. A witness is source identity/span plus method and backing family, never a stale type index or func index.
- `configureActivePromiseVectorAttempt(ctx, witness)`: called immediately after createCodegenContext in a fresh attempt, before any operation capable of ensuring Object runtime. Set the new explicit active state and protoMemberDirty=true. Do not set protoIndexDirty/protoNamedDirty artificially. Existing source scans continue to OR their legitimate facts, never reset active member demand.
- `isPromiseVectorProtocolActive(ctx)`: the production semantic-write/entry predicate; not funcMap.has. Legacy source demands retain their old effects independently.
- `verifyActivePromiseVectorAttempt(ctx, witness)`: before final fill/publication, confirm that the original witness was reached through the unchanged per-call transactional admission and that the attempt has not failed. No relaxed substitute site and no third attempt.

State transitions: initial prepared/inactive -> exact admission signal -> abandoned context; fresh active/registering -> active/ready -> finalized, or failed. No inactive->active mutation of an already emitting context. Pure facts may be reused if keyed solely on immutable source identity. No emitted Wasm instruction, local, helper handle, body array, runtime cache, mutable ABI session, diagnostic list or allocation counter crosses attempts.

The first attempt is not a separate estimator that guesses vectors. It invokes the actual old path and stops at its actual decision. It must stop before the captured-mode runtime is requested. Provider errors in the second attempt are fatal, not reasons to restart or revert to ordinary semantics.

Important unresolved nesting obligation: this branch commits its OWN argument-shape probe, but it can be reached inside an enclosing speculative expression or an early discovery emission. It is not yet proven that every such encounter corresponds to a surviving production call. Before implementing immediate restart, establish that scope for both pipelines. If an enclosing transaction can discard the encounter, an immediate signal is only a provisional witness: it cannot authorize publication of a changed no-opt-in module. At minimum, the active attempt must validate the witness against the surviving emitted-call inventory, not merely count another visit during discovery. If it disappears, the proposed two-attempt algorithm must report a lifecycle blocker during development; it is NOT acceptable to ship that new failure for an otherwise unadmitted input. Solving it requires transaction-aware admission escrow/commit notification or a separately authorized fresh legacy recovery attempt. Neither capability is demonstrated by this review. This is a concrete condition on choosing the recommended approach, not an assumption that the inner branch's comment proves outer commitment.

Cross-file example: file A has resolve override, file B has a vector all call with no override in B. Preparing the module is allowed; B remains non-observable and does not trigger restart. If file C contains its own matching override and admitted vector call, C triggers active generation, but B's call STILL uses its old per-source decision in the active attempt. Do not OR module facts into observableCombinator on retry.

Activation can itself expose a previous type/lowering defect. Therefore revalidate the original witness in the fresh attempt; if its shape changes or is lost, fail explicitly with source evidence rather than force-admit the original stale shape. Parent must measure this stability with the immutable controls. This guard is not a waiver for a failing source: such a failure remains a blocker.

## What a one-context deferred solution would actually require

If parent rejects retry cost, implement the following as a separate explicitly chosen bounded lifecycle project; a mere `prepared` boolean is not sufficient:

1. Separate `legacyStoreDemand || activeVectorDemand` from `preparedCapacity`. reserveProtoIndexStore may reserve for capacity but every presence-gated consumer (GET_R, receiver-split GET_K, HAS_R, numeric misses, own-view substitution, for-in, set decisions, companion direct readers/writers and native-proto materialization) must retain old behavior while inactive. Neither funcMap presence nor protoIndexStoreReserved is semantic activation.

2. Separate prepared seeder handles/types from the active seeder registry. All registry inventory consumers, lazy-proto init snippets, companion dispatch and own-key/descriptor readers see only legacy-active plus admitted-active brands. The current registry cannot serve both purposes unchanged. Dependencies/types are prepared while registration is open; actual brand activation cannot mint types/imports at finalization. Previously emitted lazy singleton initialization needs a recorded insertion site, including already-built Array/Promise snippets, so companion initialization occurs before relevant reads/writes and does not reseed.

3. For each omitted reader arm, record a typed semantic insertion site with target/key/Receiver locals and its exact legacy continuation. Activation splices fresh instructions before that continuation. Build at most once; attach deferred instructions to a shift-maintained owner if any indices are baked early. Do not patch by positional array offset after arbitrary prependers, by shared instruction identity reachable twice, or by recompiling helper bodies.

4. Record source-order write sites, not merely current cache values. Both alternatives must preserve target/key/RHS ordering and assignment/delete results. Nonfunction RHS presently declines the legacy interceptor; compiling a different canonical RHS later is not a safe additive splice. Define a shared one-evaluation lowering at the original site and prove its inactive output is byte-identical. Candidate statements otherwise discarded during collection require retained source-order metadata without causing new inactive compilation/effects. The two compileModuleInitBody passes need per-emission site ownership: never activate the abandoned discovery body's site or duplicate a surviving write.

5. Prepared types/globals/functions can influence indices, name counters, ABI/layout inventories, dispatch construction and source lowering even when DCE removes them. DCE alone does NOT establish no-opt-in byte parity. A complete reversible preparation allocation transaction, or a proven canonical output normalization, is required if any false-positive demand alters bytes. Current rollbackSpeculative does not undo runtime caches and is forbidden across late-import flushes; it is not that transaction.

6. On successful exact committed vector admission activate exactly once, flush pending insertion sites (including earlier overrides) and keep later emission directly active. Failed/unadmitted probes activate nothing. Finalize with no activation must retain exact legacy bodies and metadata and produce byte/behavior parity. Activation failures are fatal, never silent missing-arm success.

This is sound only when all six obligations hold. It is not necessary if the fresh-attempt strategy is accepted. The deferred plan's broad reader and allocation-authority edits appear riskier for this held PR than a reviewed fresh-generation boundary, but that is a design judgment, not a measured performance or correctness result.
