# #3425 — Align merge-group Test262 compiler pool with published baseline

## Problem

The host oracle-v8 baseline published for compiler `852c40a9` was generated by
`.github/workflows/refresh-baseline.yml` with its default compiler pool size of 4. The authoritative merge-group gate in `test262-sharded.yml` instead uses a
fallback pool size of 3. Compiler-pool contention affects `compile_timeout`
classification, so candidates and the baseline are not directly comparable.

The mismatch produces systemic bidirectional host noise across unrelated PRs:

- Porffor PR #3287 run 29638679403: 109 pass→compile_timeout, 95 non-timeout
  regressions, 168 improvements, and aggregate compile time 21.1% faster.
- Unrelated PR #3345 run 29638556351: 98 pass→compile_timeout, 95 non-timeout
  regressions, 175 improvements, and aggregate compile time 24.1% faster.
- Unrelated PR #3344: 104 timeouts, 83 non-timeout regressions, and aggregate
  compile time 26% faster.

Standalone guards pass, and the repeated cross-PR signature shows an execution
environment mismatch rather than a Porffor compiler regression.

## Root cause

`refresh-baseline.yml` declares and falls back to `COMPILER_POOL_SIZE=4`, while
`test262-sharded.yml` declares and falls back to 3. A `merge_group` event has no
`workflow_dispatch` inputs, so the sharded workflow's expression fallback is
the effective pool size for the required gate.

## Scope

- Align the sharded workflow's dispatch default and non-dispatch fallback to 4.
- Document that baseline publication and merge-group comparison must move
  together.
- Add a focused workflow contract test for the shared pool-size invariant.
- Do not change regression thresholds, allowances, oracle semantics, baseline
  contents, or standalone classification.

## Acceptance criteria

1. Merge-group Test262 shards use `COMPILER_POOL_SIZE=4` by default.
2. Manual sharded runs default to the same pool size as baseline refreshes.
3. A focused test fails if either workflow drifts from the pool-4 contract.
4. A future audited move to pool size 3 has a documented path: validate and
   update both workflows together after intentionally publishing the matching
   baseline.

## Implementation summary

Updated `test262-sharded.yml` so both its manual dispatch default and its
non-dispatch event fallback use four compiler workers, matching
`refresh-baseline.yml`. The adjacent comment records why pool size is part of
the comparison contract and requires any future audited move to three workers
to update both workflows together after validating the matching baseline.

Added `tests/issue-3425.test.ts` to pin the sharded and refresh workflow defaults
and fallbacks at four workers, plus the documented two-workflow follow-up path.
No regression thresholds, allowances, oracle behavior, baseline artifacts, or
standalone classification changed.
