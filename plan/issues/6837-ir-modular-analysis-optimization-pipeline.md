### Exact phase-one source contract

**NEW `src/ir/analysis/function-allocation-analyses.ts`**:

```ts
export interface FunctionAllocationAnalysisSelection {
  readonly ownership: boolean;
  readonly escape: boolean;
}
export function analyzeFunctionAllocations(
  fn: IrFunction,
  registry: AllocSiteRegistry,
  selection: FunctionAllocationAnalysisSelection,
): void;
```

Use type imports from `../core/nodes.js` and `./alloc-registry.js`, and value imports of the existing `analyzeEncoding`, `analyzeOwnership`, and `analyzeEscape` from their analysis-owned modules. No program-layer, frontend, environment, backend, legacy facade, or TypeScript dependency. The implementation is the following fixed direct-call sequence, with no descriptor list or result envelope:

1. `analyzeEncoding(fn, registry)` always.
2. If `selection.ownership || selection.escape`, call `analyzeOwnership(fn, registry)` exactly once and keep its exact returned object in a local.
3. Inside that branch, if `selection.escape`, call `analyzeEscape(fn, registry, ownership)` exactly once.
4. Return `void`. Do not clone inputs/results, create a new registry, clear metadata, catch/wrap failures, publish counters, verify IR, or read environment variables.

The `selection` is an internal structural subset, not a new trust/authentication boundary. Existing `IrPreparationControls` structurally satisfies it, so the caller passes its existing controls object without allocating a new object per function. Preserve access/short-circuit order (`ownership || escape`, then `escape`) and synchronous failure propagation. No default argument or reinterpretation of undefined/unknown flags is added.

**`src/ir/program-middleend-ir.ts`**: replace only the final lines 125–129 analysis body with `analyzeFunctionAllocations(fn, allocations, controls)` and adjust imports. Keep `analyzeEncoding` imported for the earlier encoding-only loop at line 72. Remove only the now-unused ownership/escape imports and add the new leaf import. Leave population checks, final return, verifiers, all hygiene/module transformations, controls and counters exactly where they are. The public optimizer and `runHygienePassesIr` signatures/exports are unchanged. The new leaf deliberately returns no envelope: no phase-one consumer needs ownership/escape results outside the existing local chain.
