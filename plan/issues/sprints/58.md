## Benchmark fidelity track

Make the landing-page edge-serverless benchmark **honest and
company-agnostic**: strip commercial platform names from the framing, and
replace the process-spawn "cold" lane with a model of how production edge
runtimes actually serve a request — a per-request context/instance from a
**warm, resident engine**.

| ID                                                                 | Title                                                                                             | Feasibility | Status | Arch spec?         | Depends on                      |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- | ----------- | ------ | ------------------ | ------------------------------- |
| [#1764](../1764-wasmtime-bench-production-serverless-scenarios.md) | model production edge-serverless per-request instantiation (warm engine), not full process spawns | hard        | done   | **YES — in issue** | #1760 (warm lane), #1580, #1746 |

**Context:** label genericization already landed (Deliverable 1 of #1764's
originating PR). The remaining work is the **measurement change**:

- **JS cold** → `node:vm` createContext + run against a warm V8
  (isolate-per-request analog; `vm` is a lighter lower bound, optional
  `worker_threads` upper-bound row).
- **Wasm cold** → warm wasmtime `Engine` + fresh `Instance` per request
  (pre-instantiated/pooled, Wizer-style). **Main cost:** `wasmtime run` CLI
  can't pool — needs a wasmtime **embedding** (Node binding if one exists,
  else a minimal Rust/C host, or in-Node `WebAssembly` API as a same-engine
  fallback with the Cranelift-vs-V8 tradeoff noted).
- **Warm** lane (#1760) is already faithful — re-label only.

**Sequencing:** #1764 builds on #1760's in-process warm lane. The dev should
first verify the wasmtime-embedding landscape (is there a maintained Node
binding?) and record the finding before choosing the Wasm-lane mechanism — if
a Rust/C host is required, that build step is the primary implementation cost.
