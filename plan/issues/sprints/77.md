## Retrospective

### Conformance — the headline number went DOWN, and that is the win

| | window begin | at freeze |
|---|---|---|
| host pass / total | 30,364 / 43,102 | 29,856 / 43,099 |
| `ORACLE_VERSION` | 10 | 12 |

**Do not read −508 as a regression.** `ORACLE_VERSION` was bumped twice inside
this window (10 → 11 → 12), the 11 → 12 step being `69493a7`, the declared
re-baseline for the #3603 host de-inflation. The oracle bump **is** the
verdict-logic change, so rows are classified differently on *both* sides of the
comparison — the two counts are different quantities and no arithmetic converts
one to the other. The count fell because the measurement got honest, not
because the compiler got worse.

Standalone highwater at freeze: **22,626** pass (official 22,394 / 43,106),
recorded 2026-07-25.

### What went well

- **The de-inflation actually landed.** Vacuous passes had been inflating both
  lanes; #3603 S1 shipped with a declared re-baseline rather than by quietly
  absorbing the delta.
- **A real merge-queue deadlock was root-caused and cleared** — a change-scoped
  `trap-growth-allow` resolves from the change-set, so it applied at PR level
  and evaporated in the post-merge promote (`tolerance 0`), pinning the
  baseline and failing every push identically. Blast radius was four PRs parked
  with identical misleading verdicts.
- **The report-page outage resolved.** `benchmarks/results/test262-current.json`
  had frozen at `15:43Z / 30390-43098`; it is now committing every few hours
  (verified through 2026-07-30 20:44).

### What didn't

- **Nobody froze at the rollover** — hence the caveat above. `freeze-sprint.mjs`
  still has no wired budget source (#2751 open dependency), so the freeze
  depends on a human running `--force` at the right moment, and that is exactly
  the thing a closing budget window makes unlikely.
- **A green job is not evidence it did its work.** The summary sync reported
  SUCCESS five times while committing nothing (#3658); the `quality` gate's
  early `bash -e` abort skips later gates while the step that ran looks fine.
  Same shape, twice.
- **`git worktree prune` was run from inside the container and deleted the host
  session's live worktree registrations.** The repo is shared: the host sees it
  at `/Volumes/Archiv Mini/...` with worktrees under `/private/tmp/js2-*`, which
  are invisible from `/workspace` and therefore reported `prunable`. One shared
  `.git`, one registry. Committed work survived (shared object store);
  registrations did not. Recovery is host-side `git worktree repair`.
  `prunable` in this repo means "not visible from here", never "stale".
- **`--dry-run` is advertised in `freeze-sprint.mjs`'s usage block but gated
  behind the trigger check**, so a bare `--dry-run` prints the no-op message and
  previews nothing. `--force --dry-run` works.

### Action items

1. Wire the budget source so freeze fires on its own (#2751) — the manual
   `--force` path has now demonstrably been missed.
2. #3658 — make the summary sync **fail loudly** when it finds new baseline data
   and produces no commit. The visible symptom is fixed; the hardening is not.
3. #3659 — replace the stakeholder-directed **unmeasured** 2500
   `regressions-allow` ceiling with measured + documented margin, now that v12
   merge_group measurements exist. Record gross-fixed and honest-regressions
   separately, never a net.
4. #3660 — a `trap-growth-allow` is consumed by exactly one promote run; an
   unrelated failure of that run re-creates the wedge.
5. Move `--dry-run` ahead of the trigger gate in `freeze-sprint.mjs`.
6. Never run `git worktree prune` from the container; treat worktree cleanup as
   a host-side operation.

### Known limitation of this record

`reconcile-tasklist.mjs` reports a set of issues whose fixing PR has merged but
whose frontmatter still reads `ready`/`in-progress`. Those did **not** freeze
into this window and instead rolled forward, so the "79 completed" figure is a
**floor, not a census**. They were deliberately not bulk-flipped: the matcher
keys on PR titles, and `#N` collides between issue ids and PR numbers, so a
blind sweep would mislabel. Flipping them needs per-issue verification.
