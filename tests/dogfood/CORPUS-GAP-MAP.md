# Acorn differential corpus — gap map (#1712 umbrella)

Generated by `tests/dogfood/acorn-corpus.mjs` (run: `pnpm run dogfood:acorn-corpus`)
against **current main** (acorn@8.16.0 pinned), **re-run 2026-06-30** after the
`#2838`/`#2325` return-wall + dynamic-dispatch family landed.

The harness compiles the pinned acorn entry module **once**
(`skipSemanticDiagnostics: true`), instantiates it, `wrapExports`, then diffs
`parse(input)` for every corpus input against node-acorn (the **same** pinned
tarball = oracle, zero version skew) with `diffAst({ maxDivergences: 100000 })`
— **UNCAPPED** (the default cap of 8 hid real divergences twice in prior
sessions). Each divergence is classified **QUIRK** (cosmetic host-marshalling:
`sourceFile` extra field, booleans as i32 0/1) vs **REAL** (everything else).

## Summary (post return-wall landing, 2026-06-30)

`inputs=22  equal±quirks=13  REAL=8  compiled-threw=1  oracle-error=0`

**The THROW class collapsed 10 → 1.** When the corpus first ran (pre return-wall),
every function body containing a `return` threw — classes, objects, generators,
destructuring, arrow-block, for-await, spread-rest, and `edge.js` all threw. After
the `#2838`/`#2325` return-wall + dynamic-prototype-accessor-dispatch family
landed, **only `regex.js` still throws** (and `acorn.mjs` self-parse, not in the
fast corpus). `new.target`, `yield <expr>`, and `for await…of` (originally filed
as **#2848**) now **parse correctly** — #2848 is resolved.

### Already tracked — NOT re-filed

- **#2838** / **#2325** — the `return` wall + dynamic-accessor dispatch. **Landed**
  between corpus runs; collapsed the THROW class 10 → 1.
- **#2841** — arrow/fn-expr `params[]` `name`/`type` dropped on host marshalling.
  In-progress (sr-paramquirk). Now that bodies parse, `arrow-params.js` and
  `edge.js` expose this broadly: **destructuring/default/rest** params also come
  back blank (`properties`/`elements`/`left`/`right`/`argument` missing), not just
  simple identifiers.

### Verified empirically (2026-06-30 re-run) — NOT closed by #2329

A concurrent claim was that `#2329` closed the template-quasis + sequence-expr
gaps. The re-run **disproves** this: `corpus/templates.js` (×21),
`corpus/sequence-misc.js` (×23), and `corpus/literals.js` (BigInt) are **still
REAL**. #2851/#2852/#2846 remain `ready`.

### Verified NOT present on current main

- **import/export spurious `attributes: []`** — did **not** reproduce.
  node-acorn emits `attributes` only at `ecmaVersion >= 2025`; the corpus runs
  **both** parsers at ev2025 (zero skew) and compiled-acorn matches. No issue filed.

## Suspected shared root cause (marshalling family)

The dominant grouped signatures are `missing-field @ .type` (×58) and
`missing-field @ .name` (×35), spanning #2841 (`params[]`), #2851 (`quasis[]`),
and #2852 (`expressions[]`). All three are "node-typed **elements of a specific
array property** come back without their fields" — one likely shared
`wrapExports` array-of-struct marshalling fix. Cross-referenced in each issue so
a dev can consolidate.
