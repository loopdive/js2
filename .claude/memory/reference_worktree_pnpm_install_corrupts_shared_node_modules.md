Agent worktrees symlink `node_modules -> /workspace/node_modules`. Running
`pnpm install` (especially a from-scratch `CI=true pnpm install`) **inside a
worktree** repoints the shared `/workspace/node_modules` top-level symlinks into
THAT worktree's `.pnpm` store. When the worktree is later removed, all ~22
top-level symlinks (typescript, vitest, tsx, prettier, …) dangle — breaking
local `tsx`/`vitest`/`tsc` for EVERY worktree that shares the store, and the
`sync-workspace-main.sh` push path.

Seen ≥2x on 2026-07-17 (once from a general worktree, once from the pr-shepherd's
`fix-3248-v2` from-scratch install during a #3248 format-repro). The `.pnpm`
store itself stays intact — only the symlinks break.

**Repair (non-destructive):** `pnpm install --offline` in `/workspace` recreates
the symlinks from the intact store. If `--offline` can't fully rebuild (missing
store entries), fall back to a full `pnpm install` in `/workspace`. Verify with
`npx tsx --version` + a scoped vitest run.

**Prevention:** don't run `pnpm install` in a worktree that shares
`/workspace/node_modules` and will be removed. For a genuinely isolated install,
the worktree needs its own node_modules (not the shared symlink). Diagnosis
tell: `ls -la /workspace/node_modules/typescript` shows a symlink into a
non-existent `.claude/worktrees/<removed>` path. Related:
[[feedback_shared_worktree_clobber_check_claim_first]].
