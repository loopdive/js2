Real npm Package Compatibility

Every package here is compiled from the exact, pinned, published npm tarball — not a reimplementation or a hand-picked snippet. Where a package's own real test suite is reproducible offline, that's what's reported; where it isn't (npm strips test/ from most published tarballs), a differential op-by-op comparison against the same package running natively is reported instead, and the two are never conflated. Performance is the compiled Wasm export measured head-to-head against the SAME pinned package running natively under Node — not a synthetic micro-benchmark. See tests/dogfood/ for the harnesses that produce this data.

How to read this: "Compiles" / "Validates" track whether js2wasm can turn the real package source into a valid Wasm module at all. "Own test suite" means the package's actual, real tests are running against the compiled output. "Differential ops" means a smaller, harness-authored set of representative calls is compared instead — a real signal, but not the same as passing the package's own test suite. A divergence in either always means a compiler bug, filed as its own issue and linked below — never worked around or hidden.
